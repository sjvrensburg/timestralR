# AGENTS.md

## Commands

- `R CMD INSTALL .` — build the project
- `R CMD check --no-manual timestralR_0.5.0.tar.gz` — run the full test suite (build the tarball first with `R CMD build .`)
- `Rscript tests/timestralR-tests.R` — run the full test suite (forecast tests skip unless `TIMESTRALR_TEST_MODEL_DIR` points at a checkpoint directory)

## Code Map

- `R/` — application source
- `tests/` — automated tests
- `inst/` — project documentation
- `man/` — help pages generated by roxygen2 from the `#'` comments in `R/`
- `src/` — native backend; one header (declarations) plus one `.cpp` (implementation) per unit, Rcpp entry points in `rcpp_interface.cpp`

## Conventions

- Document with roxygen2: edit the `#'` comments in `R/` and run `Rscript -e 'roxygen2::roxygenise()'`; never edit `man/` or `NAMESPACE` by hand.
- In `src/`, keep declarations in headers and implementations in the matching `.cpp`; after changing `// [[Rcpp::export]]` functions, regenerate `RcppExports` with `Rcpp::compileAttributes()`.
- Keep the forward pass in base R on R's BLAS; do not add a Python, torch, or external-runtime dependency for end users.
- Keep parity checks in `inst/` as developer-only scripts; the package itself must run without Python.
- Keep native and BLAS code single-threaded: no OpenMP, thread pools, or setting BLAS thread counts. Users parallelise at the R level, and nested threading causes oversubscription inside their parallel workers.
