# Developer notes

## Internal interface freeze (implemented native backend)

The following internal shapes are the contract the native implementation
in `src/` replaces drop-in. Do not change them without updating the parity
harness and golden fixtures.

- `timestral_load()` returns a `timestral_model`: `weights` (named list of
  matrices/vectors exactly as in the safetensors file, biases present only
  when the config enables them), `config` (validated list from
  `R/config.R`, with derived `head_dim`, `rope_dim`, `num_quantiles`,
  `median_index`, `supports_known_covariates`), `max_context`,
  `per_shot_horizon_patches`, `quantile_real_cap_k`,
  `extreme_value_threshold`.
- Packed layout: rows are series-major — for each series, target rows, then
  past-covariate rows, then known-covariate rows. `.assemble_rows()` returns
  `rows`/`mask` `(B * V_all, T_padded)`, `groups` (series id per row),
  `role_ids` (0 target, 1 past, 2 known; NULL when no covariates),
  `target_idx`, and padded `known_future`/`known_future_mask`.
- `.predict_block(model, inputs, observed, horizon_patches, role_ids,
  known_future, known_future_mask, groups)` returns `(R, horizon_steps, Q)`
  raw-space quantiles for one decode block. Everything above it
  (assembly, refinement, capping, mirroring, clipping) stays in R.
- Golden fixtures in `tests/fixtures/` (tiny random checkpoint + official
  outputs) pin this contract without Python or downloads.

## Native backend (implemented)

`src/` implements `.predict_block` with RcppEigen
(float64, weights held as row-major Eigen matrices in an external-pointer
session built once by `.ts_load`). `.predict_block` dispatches on
`model$session`; `backend = "R"` in `timestral_load()` keeps the pure-R
reference. Matrix products in the native code are hybrid: at >= 4e6
flops they route to the system BLAS via `dgemm` (FlexiBLAS/OpenBLAS
here), below that Eigen's own kernels are used. The threshold was tuned
by benchmark (5e5 was slower on 209M, 2e7 a wash) — a tuned BLAS is not
always better, particularly on the many medium products in attention.

The context-only path keeps a single-entry K/V cache in the session
(`KVCache` in `src/session.h`, used by `src/predict.cpp`): when a `.ts_predict_block` call's
context extends the cached context bit-for-bit (same rows, groups, and
first-observed patches), earlier patches' per-layer K/V are reused and
only appended patches plus decode tokens are computed. This is exact
(causal masks/scaler, positions depend only on the first observed patch);
multi-block native vs R agreement on 209M is ~4e-13. It cannot help once
the decode loop truncates the context at `max_context`: positions are
relative to the context start, so a sliding window invalidates cached K.
Cache memory is capped at 256 MB (estimated); above that the call falls
back to a full compute.

Speed milestones on the `native-speedups` branch (each profiled on
209M after landing; single-threaded throughout, per the constraint
below): M1 K/V cache — per-shot-8 h=1100 1.95 -> 1.20 s, no help in
the truncating context-cap case by design; M2 batched GEMMs — batch10
4.63 -> 2.29 s, context-cap 6.58 -> 5.13 s; M3 fused attention —
neutral at S <= 224 (GEMMs dominate), 8.30 -> 7.50 s at 938 patches;
M4 stacked activations — small consistent gains (5.03 -> 4.96 s).

Benchmarks (`inst/benchmark.R`, this machine):

| size | backend | univariate | long horizon | context cap | batch 10 |
|---|---|---|---|---|---|
| 5M | R | 0.05 s | 0.24 s | 0.81 s | 0.29 s |
| 5M | native | 0.02 s | 0.05 s | 0.19 s | 0.11 s |
| 209M | R | 1.20 s | 3.73 s | 14.2 s | 7.8 s |
| 209M | native | 0.50 s | 1.27 s | 4.96 s | 2.28 s |

Source layout (namespace `timestral`; each header declares a unit's
interface and documents its contract, the matching `.cpp` holds the
implementation):

| unit | contents |
|---|---|
| `session.h/.cpp` | Eigen aliases, `Cfg`, `KVCache`, `Session` (weights) |
| `nn_ops.h/.cpp` | activations, `lin` (hybrid Eigen/BLAS GEMM), residual block, RMS norm, masked softmax |
| `scaler.h/.cpp` | causal per-patch scaler, known-covariate scaling |
| `masks.h/.cpp` | time/variate attention masks, patch observation helpers |
| `attention.h/.cpp` | QKV repacking, partial RoPE, time and variate attention |
| `transformer.h/.cpp` | the interleaved transformer stack |
| `head.h/.cpp` | patch embedding, forecast tokens, monotone quantile head, denormalisation |
| `predict.h/.cpp` | context-only path (with the K/V cache) and covariate window path |
| `rcpp_interface.cpp` | `.ts_load` / `.ts_predict_block` entry points |

`src/RcppExports.cpp` and `R/RcppExports.R` are generated by
`Rcpp::compileAttributes()` from the `// [[Rcpp::export]]` tags in
`rcpp_interface.cpp`.

## Documentation

Help pages and `NAMESPACE` are generated by roxygen2 from the `#'`
comments in `R/`; regenerate with `Rscript -e 'roxygen2::roxygenise()'`
(this also runs `Rcpp::compileAttributes()`) and do not edit `man/` or
`NAMESPACE` by hand. S3 methods for Suggests-only generics (ggplot2,
tsibble, fabletools) use `@exportS3Method pkg::generic`, which R
registers lazily when the owning package is loaded.

## Parity summary (official PyTorch, torch 2.14.1, fp32)

`inst/parity_official.R`, 12 cases (univariate missing, negative trend,
multivariate, numeric covariates, long horizon, long context cap, batch of
3, observation mask, categorical past/known/multivariate, non-default
knobs): worst `max_rel` 2.0e-6 on 5M (gate: < 2e-5). 123M: 9.6e-6, 209M:
2.6e-6 on the original six cases. Synthetic config variants (biases,
no gates, no asinh, alternate schedules) in `inst/synthetic_parity.R`:
< 2.3e-7.

Threading constraint: the native backend must stay single-threaded — no
OpenMP, thread pools, or setting BLAS thread counts. R users routinely
embed package calls in their own parallel code (`parallel`, `future`,
etc.), and nested C++/BLAS threading oversubscribes cores inside their
workers. Speed work must therefore be algorithmic or single-threaded
kernel work, never added parallelism.

Profiling note (209M, temporary in-code timers, since removed): the
`lin` GEMMs dominate every benchmark case (roughly 80–95% of the summed
section time); attention scores, softmax and the probability×V products
together are at most ~12% (long-context-cap case) and ~4% elsewhere.
Within softmax, masked entries (causal/missing bias of -1e30) now skip
the `exp` call — the result is exactly 0 there, and an all-masked row
keeps the uniform probabilities — which halved softmax time (0.24 s ->
0.13 s on the long-context-cap case) for a ~2% end-to-end gain, with
bit-identical outputs. Two measured dead ends: fusing the bias add into
scalar max/exp passes, and a transposed (keys x queries) softmax layout,
both lost to the original Eigen row passes plus libm `exp`. More speed
must come from the GEMM side or from doing less work, not from the
softmax loops; the R-side refinement (`R/forecaster.R`) and scaler are
minor.
